## 策略目录命名规范

为规范版本管理与回溯跟踪，所有策略文件夹一律严格遵循以下统一命名格式：

$$\text{\{序号\}\_\{策略英文名\}\_\{首次部署日期(YYYYMMDD)\}}$$

* **序号**：三位数字编号，从 `001` 开始递增。
* **策略英文名**：小写下划线命名法（如 `smc_matrix`、`cta_trend`、`grid_arbitrage` 等）。
* **首次部署日期**：以该策略首次上线 Docker 或实盘生产环境的实际日期为准（例如 `20260930`）。

### 策略结构规范

每个策略子目录下应包含：
1. **策略源码与脚本**：包含完整、规范的中文工程级注释。
2. **策略独立文档 (`README.md`)**：
   - **策略架构与核心机制**：理论基础、特征计算、信号打分与门控模型、仓位与风控管理。
   - **两年长周期严苛回测报告**：含基准收益、最大回撤、夏普比率、蒙特卡洛压力测试、数据扰动测试、滚动窗口测试（Walk-Forward）以及样本内/样本外验证（IS/OOS）。
   - **生产环境实盘避坑指南 (Production Incident & Pitfall Log)**：详尽记录从部署至今遇到的所有重大 Bug、成因推演及底层修复方案，避免未来重复踩坑。

## 待研究策略池 (`to-research/`)

本仓库另设 [`to-research/`](./to-research) 目录，用于存放**依据公开量化资料独立整理、尚待研究与回测验证**的策略原型（区别于上表已部署运行的正式策略）。

- **核心约束**：每个策略 README 第一节写明该策略的**目标基准定义**（CAGR / Sharpe / 第三指标 / 简介 / 设计 / 参数 / 容量），**该目标基准被声明为「策略研发成功」的定义与最终约束**。
- **代码完善度**：各策略按「直接可回测程度」给出百分比评估（100% = 可直接挂数据跑回测），详见 [`to-research/README.md`](./to-research/README.md)。
- **通过验收后**，策略将按本仓库命名规范迁移为 `{序号}_{策略英文名}_{首次部署日期}` 正式目录。
