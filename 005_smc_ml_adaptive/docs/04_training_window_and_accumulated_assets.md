# SMC 机器学习自适应体系：历史数据窗口选择与核心资产沉淀指南

> 本指南针对两大核心实战问题进行深度剖析与制度化设计：  
> **问题 ①**：是否要指定近期 $N_1 \sim N_2$ 时间范围的历史 OHLCV 与交易数据进行训练？窗口如何切分？  
> **问题 ②**：LightGBM 模型与个人 Kaggle 账户中，有哪些资产是可以长期维护、越沉淀越有复利价值的？

---

## 一、核心问题 ①：训练集历史数据窗口 ($N_1 \sim N_2$) 设计原则

### 1. 明确结论：**必须指定且必须分层双轨使用，切忌“单一大锅乱炖”或“仅看最近几天”**

若只用最近 3~7 天数据训练：
- **灾难**：样本量极小（每天仅 96 根 15m Bar），树模型会把最近偶发的微观噪声当成“黄金规律”，产生极端严重过拟合。

若无脑把过去 2~3 年所有历史数据直接无差别灌入：
- **失效**：加密市场结构、费率机制、机构参与度每隔半年就发生质变（如 ETF 获批前后、清算机制改版），陈旧的远期数据会严重稀释对当前市场微观结构（如 10-09 清算踩踏）的敏感度。

### 2. 推荐的标准四层窗口切分矩阵 ($N_1 \sim N_2$)

针对 15m K 线的高频特性与离散模式分类任务，最优的数据工程窗口配置如下：

```
|-------------------------- 宏观基础底座 (6 ~ 12 个月) --------------------------| -> (学基础物理规律)
                                     |----- 近期自适应滚动窗口 (45 ~ 90 天) -----| -> (学当前微观结构)
                                                      |-- 实盘高压盲测 (最近 7~14 天) --| -> (终审安全防线)
```

| 窗口层次 | 时间范围推荐 ($N_1 \sim N_2$) | 作用与训练目标 | 权重与采样策略 |
| :--- | :--- | :--- | :--- |
| **Layer 1: 基础全天候底盘** | $T - 365\text{天} \sim T - 90\text{天}$ | 让模型见过完整的牛熊转换、深度流动性枯竭、单边暴跌与无序窄幅震荡，学会 $u$（认识不确定度）的真实边界。 | 样本衰减权重较小（如 0.3~0.5），只用于让模型识别什么是“极端异常/OOD”。 |
| **Layer 2: 活跃特征适配层** | $T - 90\text{天} \sim T - 14\text{天}$ | **核心训练集**。反映当季活跃币种的相关性、当前市场杠杆率与主流清算特征。 | 样本权重设为 1.0，使用 **Purged Walk-Forward**（5~8折）核心交叉验证。 |
| **Layer 3: 制度突变敏感层** | $T - 14\text{天} \sim T - 2\text{天}$ | 紧密捕捉最近两周的宏观突变（如 10-08 暴利期到 10-09 清算踩踏的转折）。 | 样本权重乘以 1.5（时间衰减指数平滑），重点校验模型能否输出 `NoTrade` 或 `Invert`。 |
| **Layer 4: 终极未受污染盲测** | 最近 $2\sim 3\text{天}$（或主账户实盘窗口） | **严禁参与任何训练与超参搜索**。作为安全闸门（Safety Gate）的一票否决测试集。 | 仅在模型生成后跑单向推断，模拟实盘执行。 |

## 二、核心问题 ②：长期复利资产沉淀指南

量化投研最忌讳“每次从零写脚本，训练完丢弃模型权重”。在 **LightGBM** 与 **Kaggle 账户** 中，必须制度化沉淀以下 **高价值资产树**：

### 1. LightGBM 侧应沉淀的四大核心资产

#### 资产 A：经过 Purged CV 检验的「稳健特征名录库」与「特征淘汰白皮书」
- **内容**：在多次 Walk-Forward 迭代中，记录每个因子的 **IC 衰减半衰期**、**SHAP 重要度稳定性** 与 **跨折方差**。
- **价值**：发现真正穿越周期的硬核因子（如本次实测验证的 `evidential_conflict_c`、`vol_std_32`、`mkt_evidential_u_mean`）。淘汰在 10-08 表现极好但在 10-09 彻底失效的伪拟合特征。

#### 资产 B：参数平原字典（Hyperparameter Plateau Profile）
- **内容**：Optuna 在长期搜索中沉淀下来的“安全参数范围”配置文件（例如树深必须严格控制在 $3 \sim 4$、最小叶子样本数 $\ge 30$、L1/L2 正则化 $\ge 1.0$）。
- **价值**：不再盲目重新调参，无论怎么重训，模型复杂度上限被死死锁住，天生具备抗过拟合免疫力。

#### 资产 C：离散模式分类器基座（Pretrained Multi-Asset Regime Base Model）
- **内容**：以 `regime_model_lightgbm.txt` 格式标准保存的预训练树集合。
- **价值**：支持 **增量学习（`init_model` / Continual Learning）**。每日或每两日有新数据时，无需从 0 开始消耗大量算力重训，只需基于基座模型做小步梯度微调，既保留长期稳健记忆，又具备对近期的自适应能力。

#### 资产 D：混淆矩阵与错误归因审计底稿（OOS Failure Log）
- **内容**：每次被证明预测失误的 Bar 样本（例如模型预测为 `TrendFollow`，结果实际被假突破扫损）。
- **价值**：提取这些失误样本，作为下一代 Credal Transformer 与 Dirichlet 门控的专门负样本库。

---

### 2. Kaggle 个人账户应沉淀的四大高价值资产

Kaggle 不仅是免费算力（30小时 GPU / 20GB 内存 / 极高 CPU 吞吐），更是可审计的云端量化中台：

#### 资产 ①：标准化私有数据湖版本树 (`Private Dataset: smc-crypto-governed-features`)
- **沉淀机制**：
  - 数据湖通过 Kaggle CLI 增量更新版本（`kaggle datasets version -m "update to 2026-10-xx"`）。
  - Kaggle 会永久完整保存 `Version 1, Version 2, ... Version N` 的时序快照。
- **复利价值**：
  - 彻底解决量化中最头疼的 **“回测重现性危机”**。三个月后无论市场怎么变，随时可以一键拉取任意历史版本的数据集，100% 还原当时的实验现场。

#### 资产 ②：可参数化触发的云端 Kernel 管线 (`Kernel: smc-purged-walk-forward-regime-trainer`)
- **沉淀机制**：
  - 将 Notebook/Script 解耦为无状态的自动化微服务。
  - 通过环境变量或入参接收：重训周期、Purge 窗口长度、Optuna 试验次数。
- **复利价值**：
  - 形成**云端量化计算工场**。本地或服务器的 Cron/Hermes Agent 只需下发一条指令（`kaggle kernels push`），Kaggle 就会在云端调度执行、写出日志、并输出标准化度量报告，不占用本地一分钱带宽与 CPU。

#### 资产 ③：云端模型仓库与检查点（Kaggle Models Hub / Kernel Output Artifacts）
- **沉淀机制**：
  - 每次 Kernel 运行完毕后，输出的不仅是预测结果，还有 `regime_model_lightgbm.txt`、`oos_performance_summary.json`、`feature_importance.json`。
- **复利价值**：
  - 任何下游引擎（本地 NautilusTrader、测试环境、云主机实盘）都可以通过标准命令拉取：
    ```bash
    kaggle kernels output opclown1/smc-purged-walk-forward-regime-trainer -p ./models/
    ```
  - 形成一套全自动化、高可用、具备历史追踪的 CI/CD 模型部署交付管线。

#### 资产 ④：对标顶级量化方案的私有研究分支（Fork & Ensemble Baseline）
- **沉淀机制**：
  - 将业界公认标杆代码（如方案 1 `marketneutral/purged-time-series-cv-xgboost-optuna`、方案 2 `DRW Crypto Regimes`、方案 3 `CPCV`）通过私有 Notebook Fork 建立对照基准。
- **复利价值**：
  - 每当开发出新的 SMC 因子或 Credal 算法时，直接在同一套评测基准上跑对比，量化评估新策略到底提升了几个百分点的夏普或胜率，让每一次策略优化都有据可依。
