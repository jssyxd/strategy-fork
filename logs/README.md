# 实盘日志归档 (Live Trading Log Archive)

本目录按自然日归档 `smc-trader` 实盘服务的运行日志，用于事后复盘、归因分析与事故回溯。

---

## 一、命名规范

```
{策略名称}_{yyyy_MM_dd}.log
```

* **策略名称**：与策略目录命名规范中的「策略英文名」保持一致（当前为 `smc_matrix`）。
* **日期**：以**北京时间 (CST, UTC+8)** 划分自然日。文件内容 = 该自然日内策略产生的全部日志行。

---

## 二、数据来源

服务器（`ssh jy`）上 systemd 服务 `smc-trader` 的标准输出与标准错误：

| 路径 | 说明 |
| :--- | :--- |
| `/root/live.log` | 当前运行实例的追加日志（单元文件 `StandardOutput=append:`） |
| `/root/live.log.old` | 实例轮转时保留的上一份日志 |

日志**原样归档，不做任何加工**：保留 ANSI 颜色转义序列、原始时间戳、原始字段顺序，逐字节落盘，不重排、不合并单行、不裁剪字段。

---

## 三、时间戳说明（重要）

同一文件内存在两种时间戳格式，来自两套 logger，分析时需注意：

| 来源 | 样例 | 时区 |
| :--- | :--- | :--- |
| 策略自身 logger（`PROD-MATRIX`） | `2026-10-05 17:30:00,000 [INFO]` | 北京时间 CST |
| NautilusTrader 内核日志 | `2026-10-05T09:30:00.000000000Z [INFO]` | UTC（+8h = 北京时间） |

归档时**仅按 UTC 时间戳 +8 小时换算北京日期来确定该行归属哪一天**，日志正文一律不转换。

> 分析提示：日志含转义序列，`grep` 会将其判定为二进制文件，需加 `-a` 参数；去除颜色码可用
> `sed -E $'s/\x1b\\[[0-9;]*m//g'`。

## 五、新增归档的操作方法

1. 从服务器拉取原始日志：

   ```bash
   scp jy:/root/live.log     /tmp/live.log
   scp jy:/root/live.log.old /tmp/live.log.old 2>/dev/null || true
   ```

2. 按上述归日规则切分自然日，逐字节写入 `{策略名称}_{yyyy_MM_dd}.log`。
   跨零点的行归属其**所属北京时间日期**对应的文件，因此次日导出从 00:00:00 起续接，不重不漏。

3. 更新上方「归档清单」表格，并将新文件一并提交。
