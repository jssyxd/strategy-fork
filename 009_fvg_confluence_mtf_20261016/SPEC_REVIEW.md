## 一、严重：会导致"看起来通过"

| # | 位置 | 漏洞 | 后果 | 处理 |
| :--- | :--- | :--- | :--- | :--- |
| S1 ★ | 5.4 / 九 | **主判定配置没有预注册**。单标的 6 组 × A/B × 2 套年化 × 2 条 TP1 腿 = 48 个数字，阈值表没说哪一个是"算数的那个" | 48 个数字里挑一个好看的通过，几乎是必然事件；红线 3 只要求"全表报出"，报出来仍然可以只宣传最好看的那组 | 预注册 1 个主判定：**BTC · 15m · A 口径 · 减半仓 · √365**；其余 47 个全部标注 **exploratory（探索性），只报不判定**；若主判定不通过而某个探索组通过，报告必须写明"未经预注册，不能作为研发成功依据"，该组进入下一轮 OOS 候选 |
| S2 ★ | 六.1 | **WFE 与"参数冻结"自相矛盾**。WFE 需要"训练窗内优化参数、再拿去样本外"，但红线 1 规定参数一个不动——没有优化就没有 WFE | 这条要么永远算不出数，要么算出来是个没有意义的比 | 改名 **WSR（滚动稳定性比）**，不涉及任何参数优化：把窗口切成 6 个月一段，报"avg_pnl 为正的窗口占比"与"最差窗口 / 中位窗口"两个数；门槛两选一（见附注） |
| S3 ★ | 5.4 / 六.6 | **随机入场对照组定义不清**：入场次数、方向、时段、出场结构全没写 | 对照组可以被无意识地（或有意地）设成一个必然更差的靶子，于是"显著优于随机"变成废话 | 定义成**逐笔配对随机化**：对每一笔真实入场，在同一标的、同一交易时段、同一方向的候选根中随机抽一根作为入场时刻，出场结构与距离用该根 ATR 重算；重复 **1000 次**取分布；报差值 95% 分位区间，**并单独报随机组 avg_pnl 的中位数**——若随机组本身为正（趋势市里做多就有钱），策略的正期望不算 edge |
| S4 ★ | 5.2 / 5.4 | **基准对比的暴露度不对等**。A 口径下策略大量时间空仓，波动天然低于买入持有，夏普比较对策略结构性有利 | 用夏普"跑赢买入持有"可能只是因为没在场 | 除 information_ratio 外**必须同时报**：① 按平均暴露度缩放的基准（benchmark 收益 × exposure_time_pct）；② 年化收益率差与 Calmar 对比。报告须写明"夏普高不等于更会赚钱" |
| S5 | 3.7 / 5.4 | **组合回测没有判定口径**：阈值表的字段全是单标的语言 | 组合结果好不好没有标准，容易被随口解读 | 明确：**组合回测不参与判定**，只作风险与资金占用检验（并发上限、保证金峰值、相关性、单标的归因）；判定只看 S1 的主判定组；组合层另设一个非判定门槛：三个标的的 avg_pnl 方向与单标的一致 |
| S6 | 5.4 红线 2 | **"OOS 只跑一次"没有留痕机制**：谁跑的、跑了几次、失败重跑算不算，都没规定 | "只跑一次"变成一句自我承诺，无法审计 | 新增 `oos_runs.log`：每次 OOS 执行记录时间、命令、代码 commit、结果摘要，**包括失败与重复执行**；只要跑过第二次，报告首页必须声明"OOS 已被重复执行 N 次"并说明每次差异。禁止静默重跑 |
| S7 | 5.4 / 5.5 | **"样本不足"与"不通过"混为一谈**：5.3 说 N&lt;200 不给 t 值，5.4 又拿 t≥2 当主判据，且 5.5 只说"不通过" | 199 笔时无法判定，却可能被写成"没通过"，掩盖掉"根本没测够"这个事实 | 判定改为**三态**：通过 / 不通过 / **不充分（Inconclusive）**。N&lt;200 一律判"不充分"，且不得用不通过的措辞 |

## 二、中等：执行口径会出现多种解释

| # | 位置 | 漏洞 | 处理 |
| :--- | :--- | :--- | :--- |
| S8 ★ | 3.5 | **仓位粒度与最小下单量未定义**。B 口径仓位的取整规则没写；而实盘账户只有 255 USD、BTC 一张合约名义约 830 USD，粒度会让"5% 风险预算"退化成"1 张或 0 张" | 初始权益统一取 **10,000 USDT**（研究口径，与实盘规模解耦）；仓位向下取整到整张合约；不足 1 张则**跳过该信号**并计入 `skipped_signals` 单独报数；报告附一节"若按实盘 255 USD 规模，被跳过的信号占比" |
| S9 | 3.5 | **保证金模式未定义**（全仓 / 逐仓） | B 口径固定 **cross（全仓）**，与实盘一致；并写明这会放大组合回测里多标的之间的风险耦合 |
| S10 | 3.5 | **维持保证金率（MMR）来源未定义**，"触及就按强平处理"没有依据 | 取 OKX 公开的**阶梯保证金档位表**（按名义价值分档）并在快照里记录抓取日期；拿不到则降级为"只报保证金占用峰值"，报告显式标注"未模拟强平"；同时新增硬约束：**保证金占用 ≤ 可用权益 × 80%**，超了缩仓 |
| S11 | 3.4 | **资金费结算与 K 线边界的先后未定义** | 规则：结算时刻落在持仓区间 `[开仓时间, 平仓时间)` 内即计一次，左闭右开；实现按 `fundingTime` 与成交时间戳比较，不依赖 K 线对齐 |
| S12 | 3.6 | 反手只写了"先平后开"，没写**成本翻倍与基准重算** | 明确：一次反手 = 2 次 taker 手续费 + 2 次滑点；新仓的止损/止盈基准按新信号成交价与当根 ATR 重算 |
| S13 | 附 TP1 | **减半后可能不足 1 张合约** | 若减半后不足 1 张，改为一次性全平，并记录此类情形发生次数 |
| S14 | 3.3 | B 口径下"滑点应随名义上调"没有可执行形式 | 给出形式：滑点(bp) = 1 + k × (名义 ÷ 初始权益)，敏感性 k = 0 / 0.5 / 1.0；主口径 k = 0（并在报告中写明这是保守还是激进） |
| S15 | 3.5 / 5.2 | **回测结束时的未平仓头寸未定义处理方式** | 窗口最后一根收盘价**强制平仓**（计入成本），`open_position_count` 记为 0；同时单列"若按市值持有"的差异（`unrealized_pnl`） |
| S16 | 4.2 | **指标预热期未处理**。EMA50 / ADX14 / ATR10 / linreg(12) / OBV 都需要预热，前若干根是半成品 | 每段数据**丢弃前 200 根**（≥ 最长指标窗口的 4 倍）不产生交易；取数时窗口起点相应提前 200 根 |
| S17 | 4.1 | 1h 数据来源未定，且缺一致性校验 | 主口径单独拉 1h；用 15m 合成做交叉校验（每根 1h 的 OHLC 必须等于对应 4 根 15m 的聚合），不一致即中止 |
| S18 | 4.3 | **合约规格快照未要求留档**（tick / lot / ct_val / MMR 档位会变，回测必须可复现） | 落盘 `instruments_YYYYMMDD.json` 并写进结果元数据 |

## 六、对抗性自检：我试过的三条攻击路径

1. **"挑一个好看的数字"** → S1 预注册主判定 + 47 个探索组只报不判，攻击被堵。
2. **"把对照设弱"** → S3 逐笔配对随机化 + 报随机组中位数，堵住；S4 暴露度对齐堵住基准漏洞。
3. **"悄悄重跑 OOS / 事后放宽成本"** → S6 留痕日志 + 红线 4 的版本标注，堵住。

还剩一条堵不住的，如实写在文档里：**策略本身可能已经在第三方的观察中被手工调过参数**。
这不是我们数据上的过拟合，但会削弱先验——所以本轮回测的结论边界只能是
"在 OKX 永续 15m/1h、2024-10 至 2026-10 的样本上，这组规则的表现如何"，不能外推成"这个策略有效"。
