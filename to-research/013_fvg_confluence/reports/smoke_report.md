## 一、成交时点（规格书 3.1）——**与规格书不符**

**做法**：BTC-USDT-SWAP 15m，2026-10-05 起 288 根真实 K 线；在第 3 根收盘时提交市价买单。

**结果**：

```
bar#3 O=86237.7 H=86587.4 L=86158.3 C=86585.0
>>> MARKET BUY at bar#3 close=86585.0
FILL side=BUY px=86585.0 ts=10-05 00:30        ← 同根、收盘价
```

**引擎语义**：市价单在**提交当根的收盘价**成交（不是次根开盘）。
即规格书里定义的"对照口径（乐观）"，不是主口径。

**可选的收敛方式**：策略层延后一根提交（在 t+1 根的 `on_bar` 里提交 t 根产生的信号），
成交价变为 t+1 根的收盘价——仍然只用已收盘信息，但价格不是 t+1 开盘。
次根开盘与次根收盘的价差可单独统计作为敏感性。

## 二、同根止损/止盈顺序（规格书 3.6）——**与规格书不符**

**做法**：多头持仓，挂 STOP 98.0 与 LIMIT 105.0；随后喂一根 low=96.0、high=106.0 的 K 线（同时穿过两者）。

**结果**（`bar_adaptive_high_low_ordering` = False 与 True **完全一致**）：

```
FILL type=LIMIT      px=105.0 ts=23:13     ← 止盈先成交
FILL type=STOP_MARKET px=98.0  ts=23:13     ← 止损后成交（此时仓位已平，实际是反向开仓）
```

**引擎语义**：同根内**限价（止盈）优先于止损**，且两条都成交、都按触价精确成交、**不计滑点**。
规格书 3.6 要求的主口径是"**先止损**"（悲观），引擎给不了。

**副作用提醒**：第二条成交会把已平的仓位反向开出来，策略必须自己做 OCO（成交即撤兄弟单），
且同根内撤单来不及——这就是同根歧义无法在引擎层消除的原因。

## 五、过程中的两个真实坑（已解决，记录备查）

### 5.1 "No market for ..." 的真实原因：数量精度

现象：订单一律被拒，理由 `No market for BTC-USDT-SWAP.OKX`，
且在 `add_instrument` 之后引擎日志**明确显示** `Added instrument ... and created matching engine`。

真正的日志（之前被过滤掉了）：

```
[WARN] matching_engine: Skipping quote tick for BTC-USDT-SWAP.OKX:
       Invalid bid_size precision 3, expected 2 for BTC-USDT-SWAP.OKX
```

**根因**：喂进去的 **volume/size 小数位数必须等于 instrument 的 `size_precision`**，
否则撮合引擎逐条丢弃行情 → 该标的永远没有行情 → 下单时表现为 "No market"。
第一次建 catalog 时我把 volume 统一格式化成 4 位小数（instrument 是 2 位），所以整批数据被静默丢弃。
修正后（按 size_precision 格式化）市价单、止损单全部正常成交。

**教训**：报错信息（"No market"）与真实原因（数据精度）不在一个层面，只按报错字面排查会走进死胡同。

### 5.2 两个 API 陷阱

- `Strategy` 子类**不能接受额外的构造函数参数**（Cython `__new__` 限制）→
  参数要放进 `StrategyConfig` 子类字段，或构造后用属性赋值（实盘脚本就是这么干的）。
- `MakerTakerFeeModel` 的费率参数名是 `maker_rate` / `taker_rate`；合约构造里**没有**费率字段。

## 七、需要你拍板的两处偏离（规格书 v2.2 第 3.1、3.6 节）

| 项 | 规格书要求 | 引擎实际 | 建议 |
| :--- | :--- | :--- | :--- |
| 成交时点 | 信号根**次根开盘**成交 | 提交当根**收盘**成交 | 策略层延后一根提交 → 实际变成"次根收盘"成交；并把"次根开盘 vs 次根收盘"的价差单列敏感性 |
| 同根止损/止盈 | **先止损**（悲观） | **先止盈**，且两条都成交、无滑点 | 主表按引擎原生（乐观）出；另跑一份**后处理悲观版**：同一根内同时触发止损与止盈的交易改判为止损结果，并报受影响笔数占比 |

两处都**不能靠引擎原生配置解决**（`bar_adaptive_high_low_ordering` 两种取值结果完全相同）。
