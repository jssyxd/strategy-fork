# 对账问题：根因分析与修复（2026-10-08）

## 一、现象

第一版执行器（run_bt.py）给出的 BTC 15m / A 口径 / TP1 减半仓 / 24 个月结果：

- 逐笔净盈亏合计：**-1,420 USDT**
- 权益曲线同期变化：**-5,426 USDT**
- 差额：约 **4,000 USDT**，无法解释

## 二、根因

第一版用**权益快照**计算每笔盈亏：

```
net_pnl = equity_after - equity_before      # 两次快照分别取自开仓成交与平仓成交时刻
```

问题在于：**成交回调触发时，账户状态里尚未计入该笔成交的手续费**。
于是每笔盈亏都被系统性地高估了"本笔应付手续费"这一项，误差随交易笔数线性累积——
1,186 笔 × 单笔约 3.4 USDT ≈ 4,000 USDT，正好等于缺口。

换句话说：**那 4,000 不是"未平仓浮亏"，也不是"快照取错时刻"，而是手续费没被计进逐笔账。**

## 三、修复

第二版（run_bt2.py）改为**按成交逐笔记账**，不再依赖权益快照：

| 项 | 计算方式 |
| :--- | :--- |
| 毛盈亏 | 每笔成交：`(成交价 − 开仓价) × 数量 × 合约乘数 × 方向` |
| 手续费 | 直接取成交回报里的 `commission` 字段累加 |
| 每笔净盈亏 | 毛盈亏 − 该笔所有成交的手续费之和 |
| 权益曲线 | `初始权益 + 累计毛盈亏 − 累计手续费 + 当前持仓浮盈`（自建，可逐项核对） |

并在引擎 `dispose()` 之前取一次 `portfolio.equity(venue)` 做**独立交叉验证**。

## 四、验证结果（BTC 15m / A 口径 / 减半仓 / 2024-10-01 → 2026-10-08）

```
RECON self=4573.89  engine=4573.89  delta=0.00
sum(net_pnl)=-5429.74 | gross=+1706.52 | commission=-7138.54 | open=True
```

- **自建权益与引擎权益逐分对齐（delta = 0.00）** ✓
- 逐笔净盈亏合计 -5,429.74 ≈ 权益变化 -5,426.11（差额为期末未平仓头寸的浮动盈亏）✓

## 五、修复后的真实结论

之前被隐藏的真相是：**这个策略的毛边际是正的，但被手续费吃掉四倍有余。**

| 项 | 值 | 折算到每笔 |
| :--- | :--- | :--- |
| 毛盈亏（价格部分） | **+1,706.52 USDT** | +1.44 USDT ≈ **+2 bp** |
| 手续费 | **-7,138.54 USDT** | -6.02 USDT ≈ **-8.6 bp** |
| 净盈亏 | -5,429.74 USDT | -4.58 USDT |
| 交易笔数 | 1,186 | 平均每笔 2.8 次成交 |

规格书 5.4 的"成本体检"要求 `手续费 ÷ 毛利 ≤ 40%`，实测 **418%**，
但触发的是 5.5 第 4 条：**手续费吃掉毛利后由正转负 → 成本结构本身不成立**。

> 注：10 bp 往返费率不是假设，是从本账户 2026-10-07 实盘日志逐笔反推的实测值
> （taker 0.05%，见规格书 3.2），所以这个结论不依赖任何悲观假设。
